## Embidextrous 0.9.0

Notification rules for Hall Monitor: choose which alerts you get, as many as you want. Install over 0.8.0; same app, same signing key. For alerts on every limit (daily, weekly, monthly, yearly) it needs the **Hall Monitor plugin 2.2.0.0**, released at the same time. Update the plugin first, or together. With plugin 2.1 or older the rules still work, but only for the one limit those plugins report (the one closest to running out).

### What's new in Settings → Hall Monitor
- **Notification rules.** The old "Background alerts" switch is now a list of rules. Each rule can be switched on or off and deleted, and "Add a rule" makes new ones:
  - **"When a user has used N% of their time"** (any N from 1 to 99): for example 50, 80 and 90 as three separate rules.
  - **"When a user has used all of their time"**: the alert you already know, with the +15, +30 and +60 minute buttons.
- **Your current alert carries over.** If Background alerts was on, the "used all of their time" rule starts switched on, so nothing changes until you add more rules.
- **One alert for each user and limit.** A percentage rule fires once when a limit reaches the percentage, and again only after that limit drops below it (it resets, or extra time is added). A weekly limit at 90% alerts you even while the daily limit is at 50%. The notification names the limit, for example "Alex has used 90% of their weekly time".
- **No surprise alerts.** Opening the app never alerts for something that already happened. Rules apply to all limited users.
- The rules live on this phone. Settings says when the Hall Monitor key is missing, because without it nothing is watched and no alert is sent.
- Lock-screen protections are unchanged: the lock screen shows a generic notice with no names, and the +15, +30 and +60 buttons need an unlocked phone.

### Hall Monitor plugin 2.2.0.0 (released with this)
The status now lists every enabled limit with the percent used. Nothing in your plugin settings changes. See the plugin's release notes.

### Known limits
- Checked on an emulator against a test server with the new plugin and real counted playback: the 80% alert appeared at 87% of a daily limit, with the generic lock-screen text. Not tried on a real phone or a real lock screen.
- A weekly or monthly limit firing was not tried live (it cannot fill in a few minutes); the rule logic for every limit is unit tested.
- Quiet hours, per-rule sound and priority, and rules for chosen users only are not built yet.
- Everything listed under 0.4.0 to 0.8.0 still applies.
